# 学习与讲义制作原则

> **已于 2026-11-21 经人工审阅确认。** 本文件记录跨主题的制作原则；具体讲义的教学路线、图解方案与未决问题放在 `docs/briefs/`。

## 协作

- **尊重原稿的教学意图。** 保留有教学作用的提问、类比、解释顺序和制作备注；修正科学性错误。涉及重要例子的删改或教学路线调整，先讨论再实施。AI 负责辅助打磨，而不是从原稿中提取知识点后另写一篇。
- **内容先于界面。** 正文保持单一来源；先检查科学性、解释是否连贯、图解是否有效，以及符号和公式排版，再进入预览与人工审阅。尽量复用已有站点成果，避免无收益的样式重构；未经确认不发布。

## 文字

- **面向尚未理解的读者。** 明确前置知识，从熟悉的例子和真实疑问出发，按“提出问题 → 建立图景 → 展开推理 → 得出概念与公式”的顺序讲解，而不是直接罗列定义。
- **从已有认知走向新框架。** 借助读者熟悉的知识和本篇已有概念；当新旧理解看似冲突时，说明原有直觉的适用范围，引导读者建立能统一二者的更深层认识，而非简单增加一套定义。
- **让结论在推理中出现。** 新符号和术语首次出现时解释其必要性；关键步骤让读者能够跟随推导、亲自发现结论，不先宣布答案再用计算作装饰，也不将尚未讲过的知识称作“显然”或“熟悉”。

## 图解

- **按理解障碍作图。** 先明确图要解决的问题，让图解参与推理；一张图尽量只承担一个核心任务。文字或简短公式已足够清楚的地方，不必强行配图。
- **数学准确，视觉可读。** 涉及严格几何关系的图，先建立可验证的模型，再考虑投影、遮挡、比例和标注；优先采用便于精确控制与修改的绘图方式。数学正确不能代替视觉清晰，视觉漂亮也不能代替数学正确。
- **图解直观，计算可选。** 当图解足以说明主要机制时，繁复的计算过程可以折叠；但关键推理与数学依据仍应保留。静态图能说明问题，就不必强求交互。

## 页面设计

- **交互围绕明确问题。** 任务、图像、操作和反馈尽量放在同一视野内；有限实验只用于展示机制，不能代替全局证明。兼顾触屏、键盘和窄屏阅读。

## 终稿审校

- **局部修订后检查整体。** 通读概念顺序、术语、公式及图文对应，清除旧方案留下的过渡、重复内容和废弃组件；具体制作说明只保留当前有效的决策。构建通过后仍需检查实际页面，不以代码无报错代替阅读验收。

---

**维护约定：** 只保留经过实践、可迁移的核心原则；后续修改须经人工审阅。优先合并或替换现有条目，避免不断堆积。
